# گیاکو — نسخهٔ ۳

فروشگاه فارسی محصولات مراقبت از گیاه با Go/PostgreSQL و React/TypeScript: کود، خاک و بستر کشت، ابزار، محصولات محافظتی، آموزش و مشاوره، و پک‌های مراقبت. صفحات عمومی با Node SSR و صفحات حساب و مدیریت با SPA اجرا می‌شوند.

## اجرای عادی، بدون Docker

Go 1.26، Node 22.12+ و PostgreSQL در حال اجرا لازم است.

1. از ریشهٔ پروژه `npm run setup` را اجرا کنید.
2. `.env.local.example` را به `.env.local` کپی کنید و `DATABASE_URL` را مطابق PostgreSQL خود بنویسید. اگر قبلاً `.env.local` دارید، همان تنظیمات را نگه دارید.
3. `npm start` → http://localhost:4173؛ ساخت رابط، اجرای migrationهای جدید و راه‌اندازی API/SSR خودکار است.
4. برای توسعه: `npm run dev` → http://localhost:5173.

دو حالت را هم‌زمان اجرا نکنید. راه‌انداز دیتابیس یا تصاویر را حذف نمی‌کند. راهنمای ویندوز و دسترسی مدیر: [RUN-LOCAL.md](RUN-LOCAL.md).

## امکانات

- طراحی فارسی راست‌به‌چپ و واکنش‌گرا؛ دسته‌بندی‌های تخصصی و انتخاب راهنما بر اساس مشکل گیاه.
- جست‌وجو و فیلتر نوع محصول، برند، فرمولاسیون و قیمت به تومان؛ مرتب‌سازی پرفروش‌ترین بر اساس سفارش‌های واقعاً پرداخت‌شده.
- مشخصات محصول شامل برند، وزن/حجم، ترکیبات، روش مصرف، مزایا، هشدارها، تاریخ انقضا، کشور، اقلام پک و نحوهٔ ارائهٔ خدمات.
- مدیریت قیمت به تومان با ذخیرهٔ ریالی، گالری، موجودی، محصولات مرتبط و اتصال محصول به مقاله.
- شش راهنمای آموزشی اولیه، صفحات `/blog` و `/category/:slug`، انتقال دائمی آدرس‌های قدیمی مقالات، SEO و sitemap پویا.
- سبد مهمان و حساب، علاقه‌مندی‌ها، سفارش، کوپن، مرجوعی، گزارش موجودی و خروجی CSV سفارش‌ها.
- سبد صرفاً آموزشی بدون هزینهٔ ارسال؛ سبد دارای کالای فیزیکی با تعرفهٔ ارسال تنظیم‌شده؛ جلوگیری از خرید کالای منقضی.
- نظرات خرید تأییدشده با بررسی مدیر، بازیابی رمز از طریق SMTP و مدیریت مقالات.

آموزش و مشاوره از طریق توضیح نحوهٔ ارائه و پیگیری مدیر تحویل می‌شود؛ سامانهٔ ویدئو یا دانلود خصوصی ساخته نشده است. پک‌ها محصول مستقل با موجودی مستقل‌اند؛ مصرف خودکار موجودی اجزای پک انجام نمی‌شود.

توضیح ارتقا و تنظیمات فروش واقعی: [UPGRADE.md](UPGRADE.md). گزارش بررسی: [VALIDATION.md](VALIDATION.md). تصاویر بررسی رابط: پوشهٔ `PREVIEW`.

## ساختار و بررسی

`backend/`: Go API و migrationهای افزایشی؛ `frontend/`: React و سرور SSR؛ `scripts/`: راه‌انداز محلی؛ `ops/`: بکاپ و بازیابی. Compose production شامل PostgreSQL، API، SSR و nginx است.

```sh
npm run check
npm run build
cd backend
go vet ./...
# فقط دیتابیس جداگانهٔ آزمایشی:
DATABASE_URL='postgres://.../DISPOSABLE_TEST_DB' go run ./cmd/migrate
DATABASE_URL='postgres://.../DISPOSABLE_TEST_DB' go test -count=1 ./...
```

## انتشار و داده‌های قبلی

پیش از ارتقا بکاپ بگیرید و فایل‌های تنظیمات و `backend/data` را حفظ کنید. محصولات، مشتریان، سفارش‌ها، دسته‌بندی‌ها و مشخصات قدیمی حذف نمی‌شوند. مشخصات جدید محصولات قبلی ابتدا خالی است؛ از مدیریت، نوع، دسته‌بندی و مشخصات واقعی هر محصول را تکمیل کنید.

از `.env.prod.example` برای production استفاده کنید و دامنهٔ HTTPS، اطلاعات واقعی فروشگاه، تعرفه‌ها، SMTP و درگاه را تنظیم کنید. پرداخت زنده و ارسال واقعی ایمیل به تنظیمات مالک نیاز دارند.

اگر دیتابیس قدیمی جدول `schema_migrations` ندارد، ابزار مهاجرت عمداً متوقف می‌شود. پس از بکاپ، نسخهٔ آخر migration واقعاً اعمال‌شده را مشخص کنید و روی یک دیتابیس مرجع **خالی و جداگانه** از `go run ./cmd/migrate -adopt-through VERSION` با `REFERENCE_DATABASE_URL` استفاده کنید. این ابزار تطابق کامل schema را بررسی می‌کند؛ نسخه را حدس نزنید و جدول تاریخچه را دستی پر نکنید.
